# 购买指南｜正文写作规范

**本栏目正文主线：** 购买任务 → 必要条件和优先级 → 候选与淘汰 → 购买前验证；允许得出「不需要买」。

## 1. 文章承诺

读完必须让用户**做出购买判断**：知道自己是否需要买、该按什么标准选、哪些候选该淘汰。

## 2. 开头（H1 → 首个 H2：本栏目样本中位 2 段 / 117 词）

1. **第一段先判断这是不是一个真需求**，或给一个条件句把读者分类。范例：
   `A padded cushion can improve comfort, stability, and safety during mealtimes, which can be especially helpful when your baby is new to sitting at the table for solids.`
2. **第二段给硬条件与排除项**：哪几类情况**不需要买**、哪几类**不适用**。先说排除，再说选择。
3. 不要在开头给排名或推荐清单——先定条件，再谈候选。

## 3. 正文推进（每个 H2 中位 4 段 / 155 词；24 篇里 49 节用列表、29 节用表格——表格密度五栏最高）

- 固定推进：`条件判断 → 什么时候值得 → 什么时候不值得／更简单的方案就够 → 买前检查清单 → 保养与寿命 → Final Takeaway`。
- 本栏目**表格密度最高**（29 节），因为购买决策天然是多条件矩阵。表格列应是「条件 → 判断 → 你需要确认什么」，且表前后各有一句解释。
- 每个 H2 都要能回答「对我这种情况呢」。只讲通用优点的段落视为缺口。
- **必须写出排除项**：什么情况下不买、什么情况下更便宜的方案已经够用。没有排除项的购买指南不合格。
- 不把对比写成参数朗读：先给判断，参数只作为判断的依据出现。

## 4. 证据与产品提及

- 可核查的**兼容与规格**（尺寸、宽度、功率、随附配件、适用阶段）只能来自 `../../实体库/实体变量库.csv` 的 `条件与限制`(39) / `指标与阈值`(94) / `接口与依赖`(27)；查不到就写「以商品页为准」，**不要估**。
- 实体库已有明确条目可直接引用：`兼容性依型号而定`、`功能随型号不同`、`配件以商品页为准`。该说「依型号而定」时就说，不要替用户下结论。
- **不给价格、不做品牌排名、不承诺「绝对最佳」**。
- 产品提及只在「这条检查项对应 Divoom 的哪个功能或参数」时出现，**不写型号名**（硬伤）。

## 5. 栏目专属结尾

给**选择标准**：可带走的判断依据，允许得出「不需要买」的结论。

## 6. 链接与审核

先完成正文，再按本栏目 `锚文本规范.md` 与 `../发布与链接记录/` 两张台账补链；逐条检查链接是否真的回答了锚文本所指的子问题。不承诺绝对最佳、不跳过淘汰理由、不把对比写成参数朗读。

# 设置与使用｜正文写作规范

**本栏目正文主线：** 前置条件 → 配置动作 → 中途分支 → 可观察的验收状态 → 失败时回退。

## 1. 文章承诺

读完必须让用户**完成配置并验收**：知道前置条件、按步骤配置、能观察到成功状态。

## 2. 开头（H1 → 首个 H2：本栏目样本中位 2 段 / 124 词）

1. **第一段先给关键结论**——把最有用的判断提前说一次（本栏目样本常把 `Key Takeaways` 放在第一个 H2，开头两段是它的前奏）。范例：
   `Having a small nursery, shared bedroom or apartment to create a functional baby changing station is not a problem. The goal is to maximize convenience, while keeping the area safe, clean and organized.`
2. **第二段给现场前置条件**：空间、供电、工具、需要谁在场。让读者动手前知道自己要先具备什么。
3. 不要在开头就编号步骤——先给结论和前置条件，步骤留给正文。

## 3. 正文推进（每个 H2 中位 4 段 / 180 词——单节词数五栏最高；21 篇里 42 节用列表、15 节用表格）

- 固定推进：`关键结论 → 前置审计／清点 → 方案（多个布局或路线）→ 方案对比 → 逐步执行 → 正确状态确认 → 安全检查 → Key Takeaways 收尾`。
- 本栏目单节最长（180 词），且**外链最多（中位 7，五栏最高）**：步骤类文章需要引用外部规范（安装间距、安全标准、材质与清洁要求），这是本栏目允许且鼓励的做法。
- 步骤必须**用可观察状态验收**（指示灯颜色、声音、App 里显示的连接状态、卡扣到位的手感），不要写具体按键路径或菜单层级——那随 App 版本变化。
- 给出多个方案时，**先给「选哪个方案」的判断，再给选定方案内的步骤**；不要把多个方案的操作混在同一节里。
- 安全检查不与步骤分离：涉及挂墙、承重、供电、儿童可及范围时，在对应步骤处就地给界限。
- 本栏目少用表格（15 节）：方案对比可以用表，但**操作步骤一律用有序列表**，不要塞进表格。

## 4. 证据与产品提及

- 步骤里出现的**接口、依赖、环境条件**查 `../../实体库/实体变量库.csv` 的 `接口与依赖`(27) / `场景与环境`(63) / `条件与限制`(39) / `任务与工作流`(54)。
- 涉及**安装与坠落、电气与电池、儿童与隐私**的步骤必须先给安全界限。本栏目是全库最需要「停止条件」的栏目：装不稳、供电异常、儿童可触及时都要明确写出不该怎么做。
- **不写型号名**（硬伤）；需要指代产品时用品类或功能描述。
- 产品提及只在「这一步用到了 Divoom 的哪个功能或接口」时出现。
- 范文里的操作步骤、护理建议、竞品链接不得进稿。

## 5. 栏目专属结尾

给**验收状态**：说明配置成功后应观察到什么，以及失败时如何回退。

## 6. 链接与审核

先完成正文，再按本栏目 `锚文本规范.md` 与 `../发布与链接记录/` 两张台账补链；逐条检查链接是否真的回答了锚文本所指的子问题。不做根因科普、不做设备选购、不做无关故障排查。

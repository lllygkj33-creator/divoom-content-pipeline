# 科技与信息｜正文写作规范

**本栏目正文主线：** 直接答案 → 机制／变量 → 区分和验证 → 实际边界；避免解释文章被维修步骤接管。

## 1. 文章承诺

读完必须让用户**理解**：知道现象背后的机制、关键变量，以及这个解释在什么范围内成立。

## 2. 开头（H1 → 首个 H2：本栏目样本中位 2 段 / 101 词）

前两段做完三件事，**且不许出现操作步骤、故障分流、购买建议**：

1. **第一段就给机制性答案**——用一个可检验的因果句回答 H1 的 why/how，不是「这是一个常见问题」。
   范例首句即因果：`Activated carbon reduces some airborne odor molecules by holding them in its pores, but only after those molecules reach the filter.`
2. **第一段末或第二段点名适用对象**：哪一类产品、哪个量级、哪种使用位置。
3. **第二段给失效边界**：什么条件下这个解释不成立（「如果关灯后依旧发暗，就不是环境光的问题」）。

> 反例：把 H1 限定词复述一遍当开头；先用一段行业背景铺垫；开头就上参数表。

## 3. 正文推进（每个 H2 中位 4 段 / 143 词；22 篇里 62 节用列表、28 节用表格）

- 每个 H2 承接**上一个 H2 留下的未解释变量**，不是并列罗列。本栏目样本的典型推进：
  `机制命名 → 机制展开 → 边界／例外 → 怎么观测验证 → 据此判断什么`。
- 段内节奏：先判断句，再支撑，最后落一个可观察现象。段落 60–160 词；连续三段没有小结论，说明这一节在铺陈。
- **表格用于并列变量**（如「变量 → 作用 → 什么条件下失效」），本栏目 28 节用表，是五栏中最多之一；表格前后各有一句解释，不能只有表。
- 机制段不要退化成操作步骤：一旦开始写「第一步…第二步…」，这段内容应该归 `设置与使用`。
- 本栏目列表密度也高（62 节），用于**并列条件或变量清单**，不用来写流程。

## 4. 证据与产品提及

- 本栏目是**参数密度最高**的栏目：机制里的每个 Divoom 数字（分辨率、色深、功率、接口、像素画布大小）都必须能在 `../../实体库/实体变量库.csv` 的 `指标与阈值`(94) / `部件`(51) / `功能与能力`(69) 里定位；定位不到就删掉这个数字，**不要换成近似值**。
- 机制陈述优先引用**外部规范或公开物理量**（样本外链中位 5，五栏第二高）；Divoom 参数只用来把机制落到具体量级。
- **产品提及（样本中位 12 次）只做一件事**：说明这个机制在 Divoom 的哪一类产品上表现为哪个参数。不做推荐、不给购买建议。
- **禁止出现型号名**：`产品型号` 组为空，任何型号名都是硬伤（审核官直接判 fail）。
- 竞品实例范文只借结构；其产品事实、医疗建议、外链一律不得进稿。

## 5. 栏目专属结尾

给**边界**：说明结论在什么条件下成立、什么条件下不成立，以及读者该据此判断什么。

## 6. 链接与审核

先完成正文，再按本栏目 `锚文本规范.md` 与 `../发布与链接记录/` 两张台账补链；逐条检查链接是否真的回答了锚文本所指的子问题。不写操作步骤、不做故障分流、不给购买建议。

# 逐主张证据

从大纲开始找依据；正文阶段解决关键缺口；最后才插入可读链接。按主张需要选择来源：型号能力/供电/固件/兼容用适用型号官方手册或产品页；通用机制用原始研究、标准、官方技术文档。实体变量词库用于找维度和排除漏项，不独立证明产品因果关系。来源库为固定快照；读到日期不等于今天现价或当前固件。

`evidence.json` 顶层数组，每项：

```json
{
  "id": "C1",
  "claim": "要核实的完整主张",
  "body_excerpt": "最终正文中含该主张的一段原文，可在去标签后定位",
  "status": "supported",
  "reason": "来源哪部分支持哪些范围；有何限制",
  "sources": [
    {"url": "真实公开URL或空字符串", "path": "本地快照路径或空字符串", "locator": "章节/页码/表格/段落", "checked_at": "ISO8601", "supports": "支持内容与适用型号条件"}
  ]
}
```

大纲可有 `pending`；正文封存前仅能保留 supported 的主张行，unsupported/overreach 必须修订或删除对应正文及记录。删除记录不等于删除正文，必须核对 body_excerpt。定量、因果、排除、版本时序、具体型号操作和会影响购买/安全判断的关键句逐项覆盖；不需要给每个日常过渡句堆来源。自动检查无法发现漏列的主张，最终审核必须主动扫描全文。

支持检查区分：①确实读取 ②来源可信且时效适用 ③这条主张受支持 ④没有扩大到其他型号/条件。200状态只涉及①的一部分。无法读取记 unknown，不造响应码。来源不足可删数字、收窄范围或撤销结论；不能用“约”“可能”掩盖没有依据的精确事实。

Reddit 和论坛提供疑问/个人经历，不能证明普遍机制或修复成功率。参考品牌实例提供结构，不作为 Divoom 功能事实或医学权威。不虚构实测、作者资质、独立审核或用户反馈。F14 需要写清支持证据、竞争解释与未知；结论不确定也是有效结果。

# 设置与使用｜正文写作规范

**本栏目正文主线：** 前置条件 → 配置动作 → 中途分支 → 可观察的验收状态 → 失败时回退。

## 1. 文章承诺

读完必须让用户**完成配置并验收**：知道前置条件、按步骤配置、能观察到成功状态。

## 2. 开头

写 2 段、合计约 100–150 个英文词；21 篇样本开头中位为 2 段、124 词。第一段提前说出“在具备 X 条件时按 Y 路径配置，完成后应看到 Z；看不到则回退到 W”，让读者在动手前有终点。第二段列现场前提：所需空间和环境、供电与接口、工具或材料、需要谁在场及哪些权限；未知的前提要标明先核验，不能猜设备有某插口或配件。

电气与电池、安装与坠落、防水与进水、儿童与隐私相关任务，开头先写触发停用或停止安装的迹象，再继续列准备条件。

## 3. 正文推进

多种配置路线进入同一任务时，先按现有接口、空间、权限等给“选哪条路线”的分流条件，再逐条展开；一节只处理一条路线，步骤不得在路线之间来回切换。节首先确认入场状态，操作用有序列表，每一步由“执行动作＋立刻可观察的状态”构成；分支写成“若看到 A，继续；若看到 B，停下并回退至前一步”。验收必须描述可见、可听或可检查的结果，不能仅说“点击完成”或依赖易变的菜单层级。多人协作的动作要写明谁确认供电、谁固定部件、谁检查最终状态；无人能执行某一步时先暂停配置。把“连上了”和“能完成目标任务”分开验收，前者通过不代表后者通过。

每节用 3–5 个正文段落、约 140–220 英文词说明前提、分支和验收；样本中位 4 段、180 词。将现场可能追问的“我该走哪条路”“这一动作以后应该看到什么”“没看到怎么办”分配到相邻步骤；新增一步必须改变设备或现场的可观察状态，只有重述操作的句子合并。操作用编号保证顺序并让回退点可指认，表格仅在并列前提或验收状态需要同口径对照时使用，不把连续动作压成表格；21 篇中带列表的节 42 个、表格 15 个。遇到失败，先确认哪一步的预期状态没有出现，再回到最近的可逆状态，不引入无关故障排查。全文 1200–2200 英文词，不写 H3。

## 4. 证据与产品提及

逐项对照`实体库/`：现场前提查`场景与环境`、`条件与限制`，接线和连接查`接口与依赖`、`部件`，功能可用性查`功能与能力`；验收现象查`状态与症状`，回退或误操作边界查`结果与风险`。任何距离、时间、电量、尺寸等数值须在`指标与阈值`定位，查不到即删，不得估算或写“约”。一般规范可用于核查安全原理，但不能替实体库提供 Divoom 的接口或参数。

安全停止条件紧贴对应的动作之前，特别是通电、固定、遇水或儿童可接触的节点；单开一节会让用户做完危险动作后才读到警示。Divoom 事实只来自实体库；用品类、部件或功能指代，型号名以 `../品牌资料库/产品/` 的官方命名为准，自创或拼错的型号名是硬伤；一般指代优先用品类或部件词。配件随附与可单独购买写“以商品页为准”。Momcozy / KTC 只提供步骤和验收的结构参照，其产品事实、参数、医疗建议、测试结论、链接不得挪用。不给价格、品牌排名、“绝对最佳”；编辑阶段不写内链、meta、FAQ。

## 5. 栏目专属结尾

给**验收状态**：说明配置成功后应观察到什么，以及失败时如何回退。

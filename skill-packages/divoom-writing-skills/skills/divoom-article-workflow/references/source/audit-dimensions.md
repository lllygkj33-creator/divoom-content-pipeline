## 1. experience（第一手经验）

**审什么**：文章有没有"真的动手过"的痕迹 —— 具体场景、可复现的步骤、真实遇到的边界。

**加分**
- 给出具体使用场景（桌面、床头、游戏房）下的可观察行为，而不是功能罗列
- 操作序列可复现：先做什么、看到什么、再做什么
- 主动交代权衡：同类方案之间横向比，说明为什么选这个

**扣分**
- 通篇转述产品页，没有任何"用过之后才知道"的细节
- 只讲优点，不讲代价与不适用场景

**分数区间**
- 9–10：场景、步骤、权衡齐全，读到就能照做
- 7.5–8.9：有具体操作与观察，权衡略薄
- 6–7.4：有场景但缺可复现细节
- <6：纯转述

**封顶**
1. 出现厂商级赞美 → **7.5**（在 7.0–7.8 间浮动）
2. 涉及配置/设置类内容但没有具体步骤或可观察结果 → **7.0**
3. 宣称高阶能力却没提条件或门槛 → **8.0**

## 2. expertise（专业正确性）

**审什么**：机制、步骤、比较是否**正确**。

**加分**
- 机制解释闭合：从现象能推到原因，再推回可观察结果
- 比较在同一量纲、同一条件下进行
- 术语用得准，边界说得清

**扣分**
- 因果链断裂（说了结果没说机制，或机制与结果不一致）
- 比较不同轴（拿 A 的体积比 B 的音质）
- 术语误用、概念混淆

**分数区间**
- 9–10：机制闭合、比较同轴、边界明确
- 7.5–8.9：正确但浅，或某处比较略不同轴
- 6–7.4：有明显但可修正的推理缺口
- <6：机制错误或自相矛盾

**封顶**
1. 机制描述与实体库事实冲突 → **5.0 以下**
2. 比较不同轴却给出胜负结论 → **7.0**

## 3. authoritativeness（权威与可追溯）

**审什么**：**Divoom 特有改写** —— 不要求外链，但要求**参数与实体库一致**、覆盖广度够、证据可追溯。

**加分**
- 涉及的品类、部件、功能、指标都能在 `实体库/` 定位
- 覆盖该话题的主流与边缘情形，不只是最常说的那一种
- 提到具体数值时给出来源口径（实体库的哪个变量组/条目）

**扣分**
- 出现实体库查不到的参数
- 出现型号名且与 `品牌资料库/产品/` 官方产品名不一致 → 硬伤（一致则放行）
- 只覆盖最主流情形，忽略边界

**分数区间**
- 9–10：全部可追溯、覆盖完整
- 7.5–8.9：主体可追溯，个别表述宽泛
- 6–7.4：有可定位缺口
- <6：参数与实体库冲突

**封顶**
1. 精确数值无实体库来源 → **7.5**
2. 参数与技术规格描述错误 → **5.0 以下**
3. 出现自创/拼错的型号名（与 `品牌资料库/产品/` 官方命名不一致）→ 记硬伤，**不得 pass**（不论分数）

## 4. trustworthiness（可靠性）

**审什么**：诚实度（有没有过度断言/假精确）、透明度、安全边界。

**加分**
- 主动说清适用条件与不适用情形
- 给数值时语气审慎，说明来源
- 涉及电气、电池、安装、儿童、隐私时给出明确安全边界
- 不伪装中立：品牌方内容就承认是品牌视角

**扣分**
- **假精确**：抛出很具体的数值却没有来源口径
- **过度断言**：绝对化承诺（"永不""彻底解决"）
- **高风险无护栏**：谈电气/电池/安装/儿童/隐私却不提风险边界
- **隐性带货**：全篇导向自家产品却假装中立评测

**分数区间**
- 9–10：条件、风险、来源都透明，语气克制
- 7.5–8.9：无误导断言，安全提示基础
- 6–7.4：有信任瑕疵（语气偏推销、部分数值可疑）
- <6：假精确或严重隐瞒

**封顶**
1. 涉敏感话题且**无安全边界说明** → **5.5**
2. 假精确（硬数值无来源）→ **6.5**
3. 明显推销自家产品却无利益披露 → **7.0**

## 5. hcu（Helpful Content，为人而写）

**审什么**：读起来累不累。**到达价值的时间**、**决策效率**、**认知摩擦**。

**加分**
- 结论先行：不只在开头，每个长节也有局部答案
- 按场景/条件给出可操作的选择，而不是罗列全部参数
- 扫读友好：合理分段，该用对比时用对比，不用文字墙

**扣分**
- 认知摩擦：要先读三段铺垫才看到答案
- 无决策指引：清单类文章读完还是不知道选哪个
- SEO 废话：开篇冗长背景、生硬插入无关内容
- 文字墙：大段未切分的文本

**分数区间**
- 9–10：10 秒内能找到与自己条件匹配的答案
- 7.5–8.9：结构清楚，个别节需要读完才知道结论
- 6–7.4：有明显摩擦，部分节无局部答案
- <6：读完仍无可用判断

**封顶**
1. 清单/推荐类无按场景的明确选择 → **8.0**
2. 开篇 >100 词无用背景，或生硬插入无关链接 → **7.5**
3. 内链密度 >1.5 个/百词 → **7.5**
4. 局部文字墙无要点提炼 → **8.0**

## 6. infogain（信息增益与独创性）

**审什么**：是否提供了**超出通用资料**的增量。仅仅重组现有信息（哪怕排版更好）增益依然低。

**核心三点**：独家视角、一手证据、降维整合。

**加分**
- **决策降维**：给出超越"特性罗列"的认知框架（场景化判断、对比矩阵、选型逻辑）
- **整合视角**：把分散的信息组织成可用的判断路径
- **一手来源**：Divoom 语境下指实体库与产品页的**原始事实**，用来说明"这条信息从哪来"

**扣分**
- **洗稿感**：读起来像说明书翻译，没有独立见解
- **虚假增益**：抛出惊人数字却无口径与来源
- **缺乏独立性**：用宣传话术替代判断

**分数区间**
- 9–10：给出该细分领域罕见的结构化视角
- 7.5–8.9：组织方式有增益（好的对比矩阵、细分场景解法）
- 6–7.4：有实用价值但缺独立支撑
- <6：同质化重复或空洞营销

**封顶**
1. 具体结论缺可追溯来源（Divoom 语境 = 实体库）→ **8.0**
2. 核心主张依赖厂商宣传语、无独立见解 → **7.0**

## 7. ymyl（风险与合规）

**审什么**：**Divoom 特有改写** —— 不套用 Zima 的版权/PT 词表，改用本行业真实红线。

**四类红线**

| 类别 | 具体情形 |
| --- | --- |
| 电气与电池 | 功率、充电、发热、长时间通电、电池维护 |
| 安装与坠落 | 挂墙、支架、承重、儿童可触及位置 |
| 防水与进水 | 泼溅、清洗、潮湿环境 |
| 儿童与隐私 | 儿童使用、麦克风拾音、App 权限与数据 |

**加分**
- 涉及上述话题时给出醒目的安全前提与补救措施
- 涉及 App 权限/隐私时说明数据边界
- 影响购买判断的参数给出来源

**扣分**
- **过度承诺**：用具体数值佐证优势却无来源（财务误导）
- **破坏性指令**：给出可能导致设备损坏或数据泄露的操作且无前置警告
- **敏感话题无边界**：谈电气/安装/儿童却不提风险

**分数区间**
- 9–10：风险提示细致，边界清楚
- 7.5–8.9：无误导，基础安全指引
- 6–7.4：有边界瑕疵
- <6：触及红线且无说明

**封顶**
1. 涉敏感话题且**无安全边界说明** → **5.5**
2. 大量无来源硬数值证明性能（财务诱导）→ **6.0**
3. 可能损坏设备/泄露数据的指令且无前置警告 → **5.0 以下**

## 8. 机械复核脚本

`scripts/hard_limits.py` 把原项目 `core/analyzer.py` 的 Python 硬限制层搬过来，词表与域名按 Divoom 改写。用法：

```bash
python3 scripts/hard_limits.py <稿件路径.md>
```

输出命中的降级项。**把它报出的理由原样并入 `cons`，标签用 `[系统强制降级]`，并压到对应上限。**

脚本检查：
1. 绝对化营销词（`game-changer` / `revolutionary` / `unprecedented` / `the ultimate` / `gold standard`）→ 压 7.5
2. 内链密度 >1.5 个/百词 → 压 7.5
3. 精确数值断言 ≥3 个但无外部/实体库来源引用 → 压 7.0
4. 安全敏感话题出现但无安全边界措辞 → 压 5.5
5. 出现型号名（`Divoom <Model>` 形态）且不在官方产品名库中 → 记硬伤

**注意**：脚本只做机械判定，不能替代判断。它没命中不代表没问题，命中了一定要压分。

# Divoom｜产品植入规范

本文件管一件事：**一篇文章里要不要提产品、提哪个、锚文本怎么写、谁写。**

结论来自 109 篇竞品正文的实测（`analyze_product_mention.py`），不是经验之谈。

---

## 一、竞品实测基线（先看数据，再看规则）

| 指标 | 实测值 | 说明 |
| --- | --- | --- |
| 提到自家产品的文章 | **82/109（75%）** | **25% 完全不提** |
| 品牌名首次出现位置 | 中位 **0.09**（79% 在前 1/3） | 竞品**前置品牌名** |
| **链接**首次出现位置 | 中位 **0.30** | 前中段，**不是后半段** |
| 首个链接指向 | 商品页 **64%** / 集合页 **35%** | 品类词路径存在但非主流 |
| 提及方式 | 段内自然提及 **394 节** / 含链接 152 节 / **产品级 H2 50 节** | 产品级 H2 见于 24% 的文章 |
| 集合页锚文本词数 | 中位 **2–3 词**，61% 在 3–6 词，**7 词以上为 0** | |
| 商品页锚文本词数 | 中位 **4 词**，23% 为 7–10 词 | 常用产品全名 |

## 二、Divoom 的规则（与竞品有意不同的地方要说清）

### 2.1 位置：由上下文决定，不设固定段位

- **不照抄竞品的「品牌名前置于 0.09」。** 那是品牌力充足时的打法；Divoom 前置会读成广告。
- **也不统一塞到后半段。** 竞品链接中位在 0.30，硬挪到末尾会让产品与它该回答的问题脱节。
- **规则是**：植入点 = **正文中确实在讨论该产品某项手册级能力的那个 H2**。位置服从这个匹配，前后段不限。
- **硬禁止**：不得放在开头两段（H1 之后到首个 H2 之间）。

### 2.2 形式：段内自然嵌入，禁止产品级 H2

- 竞品有 50 节「以产品为 H2」（24% 的文章）。**Divoom 一律不用。**
- 只允许**段内一句到一小段**的自然提及：这一句要服务于当前 H2 已经在讲的事，而不是另起一个话题讲产品。
- 判断标准：**把这一句删掉，这个 H2 还成立吗？** 成立才叫嵌入；不成立说明它是硬插的。

### 2.3 锚文本：按目标类型分两套

| 指向 | 词数 | 形态 | 例子 |
| --- | --- | --- | --- |
| **集合页** | **2–4 词** | 通用品类词（不含品牌名优先） | `pixel art display`、`pixel art speaker`、`karaoke speaker` |
| **商品页 / PDP** | **3–6 词**（可用产品全名，但 ≤10 词） | 官方产品名或其短名 | `Divoom MiniToo Retro Pixel Bluetooth Speaker`、`MiniToo` |

- 词数上限来自 `锚文本总规范.md`（中位 4 词，主用 3–6 词），与竞品实测一致。
- **锚文本只能取自 `品牌资料库/产品/<handle>.md` 的 `锚文本候选`**，不自创。
- 同一页不得重复同一锚文本；锚文本必须描述目标页真实内容。

### 2.4 频率与「不植入」

- **一篇最多 1 个产品、1 处提及。** 竞品 75% 的文章提产品，但那是品牌站；Divoom 越克制越可信。
- **不植入是完全正常的结果**（竞品有 25% 不提）。
- 一篇里不得同时出现多个产品的并列推销。

### 2.5 两条路径

```text
路径 A（软，优先）：正文提到「通用品类词」→ 锚文本 = 该品类词 → 链到集合页
路径 B（硬，需更强依据）：正文在讲某项具体能力 → 锚文本 = 官方产品名 → 链到 PDP
```

- **优先路径 A**：不点名产品，只把品类词链到集合页，由集合页往下导到 PDP。竞品 35% 的首链就是这么做的。
- **路径 B 只在上下文确实在讨论该产品的某条手册级能力时才用**，且必须写明依据。
- 两条路径都要求：**正文原本就在说这件事**，不是为了让链接成立而改话题。

## 三、该不该植入：四条硬判据（全过才植入）

1. **有上下文**：正文某个 H2 确实在讨论这个品类或这项能力（不是"沾边"）。
2. **有能力对应**：该能力能在 `品牌资料库/产品/<handle>.md` 的 **`能力小节`** 或 `包装清单` 里找到；找不到就是没有依据，**放弃**。
3. **有实体支撑**：这条能力能在 `实体库/` 找到对应实体（否则正文那句话本身就站不住）。
4. **删掉仍成立**：把拟插入的那句删掉，所在 H2 依然完整。不成立 = 硬插。

**任何一条不过 → 不植入。** 不为凑数植入。

## 四、职责切分（重要）

**产品经理只出方案，不写段落。** 段落由**内容编辑**写。

| | ②b 产品经理 | ② 内容编辑 |
| --- | --- | --- |
| 产出 | **一段的 brief** | **段落原文** |
| 内容 | 产品键、PDP_URL、锚文本（含词数）、插入位置（哪个 H2 / 段前段后）、**匹配依据**（引哪条手册能力 + 对应实体库哪组）、**这段要讲哪几点** | 按《本栏目正文写作规范》六节写，与前后段衔接 |
| 字段 | `work/runs/<runId>/01b-product.json`（**不进最终 20 键**） | `body_markdown` / `html` |

**为什么必须这样切**：

1. **字段归属**：`body_markdown` 的唯一属主是内容编辑。多一个写入者会让权责表失效。
2. **回环会断**：审核官判 `revise` 时打回给**内容编辑**。若那段是 PM 写的，编辑要替别人改稿且不知其所以然。
3. **文风会分叉**：编辑是唯一握着《正文写作规范》的人。竞品实测也显示 394 节是**段内自然提及**——散文必须合文风。

## 五、产品经理的作业顺序

1. 读正文，标出**所有提到品类词或与某类产品能力相关**的 H2 段落位置。
2. 扫 `品牌资料库/产品.base`（先按 `商品类型` = `单品` 过滤），按 `话题关键词` / `分类` 缩到 2–5 个候选。
3. 打开候选的 `品牌资料库/产品/<handle>.md`，读 `能力小节`；再到 `手册/<key>.md` 核对上下文。
4. 对每个候选跑第三节的**四条硬判据**；选出唯一一个（或一个都不选）。
5. 定锚文本：走路径 A 还是 B，按 2.3 的词数与形态规则，从 `锚文本候选` 里取。
6. 写 brief：产品键 / PDP_URL / 锚文本+词数 / 插入位置 / 匹配依据 / 这段要讲哪几点。

## 六、与竞品的有意差异（一句话备查）

| 项 | 竞品做法 | Divoom 做法 | 为什么 |
| --- | --- | --- | --- |
| 品牌名位置 | 前置（中位 0.09） | 不前置（禁放开头两段） | 品牌力不足，前置像广告 |
| 链接位置 | 中位 0.30 | 由上下文决定 | 硬挪会与所答问题脱节 |
| 产品级 H2 | 24% 文章使用 | **一律不用** | 品牌力不足以支撑独立产品段 |
| 单篇提及数 | 常见多处 | **最多 1 处** | 克制度换取可信度 |
| 谁写 | — | **编辑写，产品经理只出方案** | 字段归属 + 回环 + 文风 |

# Divoom 内容资料库

本库供 Codex **一篇一篇**读取和执行：写作前读实体库与该栏目三份规则，写完回写发布台账。

## 目录结构

```text
Divoom 内容资料库/
├── 实体库/
│   └── 实体变量库.csv
├── 科技与信息/     标题与大纲规范.md · 锚文本规范.md · 正文写作规范.md
├── 帮助与提示/     标题与大纲规范.md · 锚文本规范.md · 正文写作规范.md
├── 产品对比/       标题与大纲规范.md · 锚文本规范.md · 正文写作规范.md
├── 购买指南/       标题与大纲规范.md · 锚文本规范.md · 正文写作规范.md
├── 设置与使用/     标题与大纲规范.md · 锚文本规范.md · 正文写作规范.md
└── 发布与链接记录/
    ├── 已发布文章.csv
    └── 待补内链.csv
```

五个栏目直接位于根目录，**没有**“五类栏目”这一层实际文件夹；也不建通用知识图谱、单实体笔记、Canvas 或第六个栏目。

## 先选栏目，再选类型

| 栏目 | 正文必须交付的结果 | 典型分流边界 |
| --- | --- | --- |
| 科技与信息 | 解释机制、根因、变量、边界 | 如果读者要实际修好故障，转帮助与提示 |
| 帮助与提示 | 按症状检查并恢复，或判断何时停用／求助 | 如果读者要从零完成正常配置，转设置与使用 |
| 产品对比 | 同一任务下比较相同维度，给条件赢家 | 如果核心是是否购买及预算分配，转购买指南 |
| 购买指南 | 依据需求、约束和成本决定是否买、买哪类 | 如果只解释两个变量的关系，转科技与信息 |
| 设置与使用 | 在具体场景完成配置并验收可观察结果 | 如果配置已失败且要排障，转帮助与提示 |

**代入规则：** 先从 Divoom 实体变量表与真实问题取对象、条件、现象、结果等槽位，再选择标题公式。`Why`、`Can` 等词不是必须相邻或固定在句首，语序须符合自然英文和搜索意图。H2 箭头表示要回答的子问题顺序，并非逐字 H2 标题；按问题删减节点，不能删掉 H1 所承诺的限定条件。F 前缀在「信息类」和「设置与使用」两个命名空间中分别编号，不能混用。状态为「推演」「正文未核实」「跨栏目」的行保留供规划，不能对外声称是已验证 Momcozy 写法。

**命名空间：**

| 栏目 | FX 命名空间 | 已导入行数 |
| --- | --- | --- |
| 科技与信息 | `F1–F14` | 14（含 F14 候选） |
| 帮助与提示 | `S1–S12` | 12 |
| 产品对比 | `PC1–PC10` | 10 |
| 购买指南 | `BG1–BG11` | 11 |
| 设置与使用 | `SU1–SU13` | 13 |

> 设置与使用用 `SU` 前缀，与科技与信息的 `F` 区分开。需求文档里写了 `设置与使用 F1–F13`，按「文件路径也必须用于区分」的要求落成 `SU`，避免两个 F 命名空间相撞。

## 每个栏目的文件

| 文件／目录 | 内容 | 格式 |
| --- | --- | --- |
| `标题与大纲规范.md` | FX 主表（公式／H2 箭头／状态）+ 正文结构抽样 + 单篇检查 | 笔记 |

| `实例.base` | 本栏目实例的数据库表格：FX 编号／标题／来源／图片数／正文字数／正文摘要，并保留 `正文` 全文列 | Bases 数据库 |
| `实例/` | 每篇实例一篇笔记，**正文同时写入属性与笔记正文，一一对应**：`实例ID/栏目/FX编号/标题/实例URL/来源站点/图片数/正文字数/正文`，笔记正文是完整 markdown（含图片） | 笔记 |
| `实例正文.md` | 同批实例的连续阅读版（汇总表 + 各篇正文） | 笔记 |

`正文` 属性存整篇正文，供 Bases 直接取出；表格里另用公式列 `正文摘要`（前 220 字）保证可读。

**正文已做噪音清洗**（脚本 `clean_bodies.py`）：只保留文章正文，去除整站导航与促销轮播、相关文章／推荐商品／编辑器推荐、作者简介与头像、免责声明块、支付图标、分享按钮、标签列表、购物车面板、加购按钮与商品卡价格行。
清洗只作用于库外 `work/bodies/`，不改动事实内容；每篇仍保留文章内图片（共 266 张，原始链接）。

实体库与台账同样是笔记格式：`实体库/实体变量库.base` + `变量组-*.md`；`发布与链接记录/已发布文章.md`、`待补内链.md`。
库内**不生成 CSV**；原始样本 CSV 存放在库外 `work/samples/`，只作数据源。

**竞品正文只作结构参考**：其产品事实、医疗建议与目标链接不得写进 Divoom 成稿。

## Codex 单篇调用流程

1. 读 `实体库/实体变量库.csv` 与相关 Divoom 产品资料。
2. **只读**该栏目的三份规则。
3. 查 `发布与链接记录/已发布文章.csv` 去重。
4. 路由 FX → 定 H1／H2。
5. 写正文并审核。
6. 补现有内链，或登记链接机会到 `待补内链.csv`。
7. 发布后把 URL 与日期写回台账。

**一次只推进一篇，完成并记录后再开始下一篇。**

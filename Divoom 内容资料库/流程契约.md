# Divoom 内容流水线｜流程契约

本文定义五个角色的**输入、输出、文件命名与回环规则**。skills 由人提供，契约只管「谁在什么时候读什么、写什么、写到哪」。

**角色 prompt 一律用固定文本**（不变的角色 prompt），变化的内容一律走**文件节点注入**。

## 一、五角色与链路

```text
用户主题
   ↓
① brief官        检索实体库 + 外部真实搜索需求 → 产出 brief
   ↓
② 内容编辑       拿 brief + 本栏目规范 → 第一轮正文（H1 + HTML + body）
   ↓
③ 审核官         对照实例正文多维打分（EEAT / HCU / YMYL）
   ↓  不达标 → 带修改意见打回 ②（最多 N 轮）
   ↓  达标（放行）
④ SEO优化师      补齐 meta title / description / summary / 锚文本 / 内链 / 外链
   ↓
   ⚙ HTML同步    由编排器从 SEO 后的 body_markdown 确定性重建带链 HTML
   ↓
⑤ GEO优化师      基于带链正文做残余覆盖复核 + FAQ 或收尾段落
   ↓
final.json + final.html（汇总节点写 generated_at）
```

## 二、角色权责边界

| 角色 | 只做 | 绝不碰 |
| --- | --- | --- |
| **① brief官** | 检索实体库、查外部真实搜索需求、润色标题、定栏目与 FX 编号、给大纲逻辑链路与参考 URL | 不写正文、不选锚文本 |
| **② 内容编辑** | 按 brief 写 H1 + 大纲 + 正文 + HTML，产出不含 meta/url/summary 的 JSON | 不写 meta、不选锚文本、不判 FAQ |
| **③ 审核官** | 对照实例正文打分、给可执行的修改意见、决定放行或打回 | **不改稿**（只出意见与分数）、不含 SEO/GEO 的活 |
| **④ SEO优化师** | 选锚文本与内链（**只能指向已发布台账里的真实 URL**）、外链、写 meta title/description/summary | 不改正文观点与结构、不编造链接、不做 FAQ |
| **⑤ GEO优化师** | 按 query fan-out 判断缺口、写 FAQ 问答或收尾段落、给 E-E-A-T 观察 | **不改正文一个字**、不选锚文本 |
| **⚙ 编排器（HTML同步）** | 在 SEO 之后、GEO 之前，从 `03-seo.json` 的 `body_markdown` **确定性重建带链 HTML**（保留可见文字与标题），交给 GEO 在尾部追加 | 不参与写作、评分、选链 |

## 三、每轮的产物与字段归属

**字段只增不减**：后一角色只补自己的字段，不得清空前序字段。

| 轮次 | 产物文件 | 本轮新增／拥有的字段 |
| --- | --- | --- |
| ① brief | `00-brief.json` | `topic` `column` `fx` `polished_title` `search_demand` `outline_logic` `reference_urls` |
| ② 编辑 v1 | `01-draft-v1.json` | `h1` `body_markdown` `html` |
| ③ 审核 v1 | `02-review-v1.json` | `scores` `verdict` `revision_notes` |
| ② 编辑 v2（被打回时） | `01-draft-v2.json` | 覆盖 `h1` `body_markdown` `html`，并记录 `revision_of` |
| ③ 审核 v2 | `02-review-v2.json` | 同上 |
| ④ SEO | `03-seo.json` | `title` `meta_description` `summary` `internal_links` `external_links` `pending_links` `body_markdown`(仅插入链接) |
| ⑤ GEO | `04-geo.json` | `faq` `closing_paragraph` `fanout` `eeat_notes` |
| 汇总 | `final.json` `final.html` | 合并以上全部，`url` 留空待发布 |

**回环版本命名**：不覆盖历史。编辑每被退回一次就出一版新文件（只有 `v1`、`v2` 两版），审核同理。这样最后能查到「改了几轮、每轮为什么被打回」。

## 三点五、HTML 同步闸门（编排器负责）

SEO 与 GEO 两份 skill 都明确依赖这一步，**不得跳过**：

1. SEO 只改 `body_markdown`（插入链接），**不改 `html`** —— `03-seo.json` 里的 `html` 仍是审核时的无链接版本。
2. 编排器在交给 GEO 之前，**由 `03-seo.json` 的 `body_markdown` 确定性重建带链 HTML**（正文可见文字与 H1/H2 保持不变，链接就位）。工具：`tools/html_sync.py`（纯标准库，命令 `python3 tools/html_sync.py <body.md> -o <out.html>`）。它会在可见文字、H1/H2 数量或链接数量对不上时**直接报错退出**，不静默降级。
3. GEO 只能在这份**带链 HTML** 的尾部追加 FAQ 或收尾段，生成 `04-geo.json` 的 `html`。从旧的无链接 HTML 追加视为失败。
4. 汇总节点校验最终 JSON **恰好 20 键**，写 ISO `generated_at`，输出 `final.json` 与 `final.html`；**JSON 里的 `html` 必须与 `final.html` 字节一致**。

## 四、最终 JSON 字段（固定 20 个，不增不减）

```json
{
  "topic": "用户原始主题",
  "column": "科技与信息|帮助与提示|产品对比|购买指南|设置与使用",
  "fx": "F1|S3|PC2|BG1|SU4 …",
  "h1": "正文 H1",
  "title": "meta title（50–60 字符）",
  "meta_description": "meta description（140–160 字符）",
  "summary": "summary（60–90 词）",
  "slug": "从 H1 生成的小写连字符 slug",
  "url": "",
  "body_markdown": "SEO 优化后的完整正文",
  "html": "正文 + FAQ 的 HTML 片段（不含 html/head）",
  "faq": [{"question": "...", "answer": "..."}],
  "closing_paragraph": "无 FAQ 时的收尾段落",
  "internal_links": [{"anchor": "...", "url": "...", "h2": "...", "type": "..."}],
  "external_links": [{"anchor": "...", "url": "...", "why": "..."}],
  "pending_links": [{"anchor_candidate": "...", "topic": "...", "h2": "...", "reason": "..."}],
  "fanout": [{"layer": "定义|条件|对比|操作|边界|成本", "question": "...", "verdict": "covered|gap_filled|out_of_scope", "evidence": "..."}],
  "eeat_notes": ["..."],
  "review": {"scores": {}, "verdict": "pass|revise|escalate", "rounds": 1, "revision_notes": []},
  "generated_at": "ISO 时间戳"
}
```

- `url` 由发布环节回填，生成时留空
- `faq` 与 `closing_paragraph` 互斥：有缺口给 FAQ，无缺口给收尾段落
- `internal_links` 必须与 `body_markdown` 里实际出现的链接一一对应

## 五、回环参数（待你确认数值）

| 参数 | 建议默认 | 说明 |
| --- | --- | --- |
| 最大重写轮数 | **2** | 第 2 轮仍不达标则交人工裁决（`escalate`），不产出第三版 |
| 放行分数 | **零硬伤 + `aggregate_eeat` ≥ 8.0 + 七维最低分 ≥ 7.0** | 七维等权，不加权；四条同时成立才 `pass` |
| 评分维度 | 见下 | 七维等权，**不加权** |
| 始终不达标 | 输出 `verdict: escalate` + 全部历史，停下来等人 | 不允许静默放行 |

**卡住等人时**：任何角色把当前关键事件上报为 `--状态 等待人工`（看板卡片转紫，顶部横幅显示「✋ 等待人工接手」）。
人工或 Codex 接手完成后，把同一事件改回 `--状态 完成`——不改回，卡片会一直停在紫色。这条是 DSH / Codex / 人混跑时的交接点。

**评分维度（初审，7 个，每个 0–10）**：`experience`、`expertise`、`authoritativeness`、`trustworthiness`、`hcu`、`infogain`、`ymyl`。
另出 `aggregate_eeat` = 前四个 E-E-A-T 维度的算术均值（一位小数）。
`fact_grounding` **不是评分维度**，而是并行的证据清单（`claim / source / verdict`），逐条核查正文断言能否在 `实体库/` 定位；它只参与「零硬伤」判定，不参与总分。

> 维度命名以 `skills/审核官/SKILL.md` 与 `skills/审核官/references/audit-dimensions.md` 为准，本节仅作摘要；两处不一致时以 skill 为准。

## 六、运行产物目录

```text
Divoom 内容资料库/work/runs/<runId>/
├── 00-brief.json
├── 01-draft-v1.json
├── 02-review-v1.json
├── 01-draft-v2.json          # 被打回时才有
├── 02-review-v2.json
├── 03-seo.json
├── 04-geo.json
├── final.json
└── final.html
```

`<runId>` 用启动时间，例如 `2026-09-29T09-40-12`。

## 七、硬约束（违反即失败，不适用「建议」）

1. **内链只能指向 `发布与链接记录/已发布文章.md` 里真实存在、已发布、可访问的 Divoom URL**；没有就登记 `pending_links`，**正文绝不留空链接或占位符**。
2. **Divoom 事实只能来自 `实体库/`；产品事实与产品名另来自 `品牌资料库/`。** 型号名必须与 `品牌资料库/产品/` 的官方产品名一致，**自创或拼错的型号名是硬伤**。
3. **竞品实例只作结构参考**：其产品事实、医疗建议、目标链接不得写进 Divoom 成稿。
4. **字段只增不减**；回环不覆盖历史版本。
5. 审核官**不改稿**，GEO 优化师**不改正文**。

# Divoom 品牌资料库｜结构说明

这里是 **divoom.com 官方内容的内部结构化镜像**：集合页、产品 PDP、场景页、以及每个产品的英文（或多语种含英文）产品手册。

**它不是内容规范，也不是写作素材。** 它只回答一个问题：**这篇文章该不该提某个产品、提哪个、锚文本怎么写。**

---

## 一、目录结构

```text
品牌资料库/
├── README.md              本文件
├── 产品.base              ★ 扫描入口（一行一产品，可排序筛选）
├── 集合.base
├── 产品/<handle>.md       ★ 单产品全量信息（PDP + 包装清单 + 手册小节 + 锚文本候选）
├── 集合/<handle>.md       集合定位与成员
├── 场景/<slug>.md         5 个官方场景页
└── 手册/<key>.md          官方产品手册正文（含英文）
```

来源与抓取方式：

| 内容 | 来源 | 方式 |
| --- | --- | --- |
| 产品结构化字段 | `/products.json`、`/collections/<h>/products.json` | 官方 JSON 接口 |
| 手册索引 | `.../assets/product-manuals.json` | 官方 JSON 接口 |
| PDP / 集合页 / 场景页 / 手册 | 各页面与 PDF | Firecrawl 抓取 + 脚本去噪 |

> 抓取与生成脚本：`fetch_brand.py`（抓，含原始缓存与 `--phase reclean`）、`build_brand_library.py`（组装）。

## 二、产品经理 agent 的工作流

**输入**：一篇文章的 `topic` / `column` / `fx` / `body_markdown`。

**步骤**：

1. **扫描候选** —— 打开 `产品.base`，用文章的 `column` 与正文主题去比对每一行的：
   `分类`、`话题关键词`、`锚文本候选`。筛出 2–5 个候选产品。
   *先按 `商品类型` 过滤：`单品` 才适合植入；`套装 / 礼品卡 / 服务` 一般不植。*

2. **定位 PDP** —— 对每个候选打开 `产品/<handle>.md`，读它的：
   - `## PDP 描述` —— 官方怎么定义这个产品
   - `## 包装清单` —— 官方口径的随附物
   - `## 手册功能小节` —— **产品到底有哪些能力**（这是判断匹配的关键证据）
   - `## PDP 正文` —— 完整官方描述

3. **判断是否该植入** —— 逐条自问：
   - 正文里有没有某个 **H2 段落**，其话题正好是这个产品的某项**手册级能力**？
   - 该段落是否在**后半段**（植入位置要求）？
   - 加上这段会不会让文章变成软文？（一次运行**最多植入 1 个产品、1 个小段落**）
   - 产品的能力能不能在**实体库**里找到对应实体？（找不到就说明这个能力没有依据，放弃）
   ≥3 项都答"是"才植入；否则**不植入也是正确结果**。

4. **选锚文本** —— 从该产品的 `锚文本候选` 里挑，并遵循 `../锚文本总规范.md`：
   中位 4 词、主用 **3–6 词**；必须指向**集合页或 PDP**；同页不得重复同一锚文本。

5. **产出建议**（不改正文，只给可执行的植入方案）：
   `产品键` / `PDP_URL` / `锚文本`（含词数） / `插入位置`（哪个 H2、段前还是段后） / `拟写小段落` / `判断依据`（哪条手册能力、对应实体库哪一组）。

## 三、字段说明

### `产品/<handle>.md` 的 frontmatter

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `产品名` | **官方 PDP 标题**（原样） | 锚文本最全的种子 |
| `短名` | 官方短名（如 `MiniToo`） | 正文里指代产品 |
| `产品键` | 官方 key，对应 `手册/<key>.md` | 关联手册 |
| `分类` | 官方分类（像素显示屏 / 像素音箱 / …） | 粗筛 |
| `商品类型` | `单品` / `套装` / `礼品卡` / `服务` / `礼品` | **植入前先过滤** |
| `PDP_URL` | 产品页地址 | 锚文本目标 |
| `价格` | 最低变体价 | 参考。**正文不写价格** |
| `在售` | 是否有可售变体 | 停售产品不植入 |
| `标签` | 官方商品标签 | 话题匹配 |
| `所属集合` | 该产品出现在哪些集合 | 集合页锚文本目标 |
| `手册` | 手册笔记相对路径 | 读能力 |
| `包装清单` | 官方手册的「IN THE BOX」 | 核对随附物口径 |
| `能力小节` | 官方手册的功能小节标题 | ★ 匹配判断的主要证据 |
| `话题关键词` | 标签＋分类＋手册小节去重 | ★ 扫描匹配 |
| `锚文本候选` | 全部来自官方命名 | 选锚文本 |

### `.base` 视图

`产品.base` 的 `产品总表` 已按 `分类 / 短名 / 商品类型 / 价格 / 在售 / 所属集合 / 话题关键词 / 锚文本候选` 排列，可直接扫。

## 四、硬约束（与主流程共用）

1. **产品名与产品事实只能来自本库。** 本库内容全部抓自 divoom.com 官方页面与官方手册。
2. **型号名的口径变了（重要）** —— 原先「不得出现型号名」是因为实体库 `产品型号` 组为空、没有权威来源。**现在本库提供官方产品名**，所以规则改为：
   **可以出现型号名，但必须与本库 `产品名`／`短名` 一致；自创、拼错、张冠李戴仍是硬伤。**
3. **正文不写价格、不做排名、不承诺"绝对最佳"。** `价格` 字段仅供内部排序参考。
4. **配件是否随附、可否单独购买，一律以 `包装清单` 与 PDP 为准**，不臆测。
5. **一次运行最多植入 1 个产品、1 个小段落**，且只放在后半段关键位置。
6. **植入不得改变原文结论**；不得把解释类文章改写成产品推荐。
7. **竞品（Momcozy/KTC）的产品事实仍不得进稿** —— 本库只含 Divoom 自家产品。

## 五、与主流程的衔接（尚未接线）

产品经理 agent **还没有接进画布**。接线的位置有一个约束需要注意：

```text
现在的链路：
  ② 内容编辑 → ③ 审核官 --pass--> ④ SEO → 🔗HTML同步 → ⑤ GEO → 📦 汇总

将来插入产品经理后：
  ② 内容编辑 → 【产品经理】→ ③ 审核官 --pass--> ④ SEO → 🔗HTML同步 → ⑤ GEO → 📦 汇总
```

**为什么必须插在 ③ 审核官之前**：植入会改动 `body_markdown`。若放在审核之后，审核结论就失效了（审核官审的是没植入的版本，最终 `final.html` 却带着植入段落）。放在审核前，审核官会连同植入段落一起按 `ymyl` / `infocann` 维度把关，避免植入变成软文。

**字段归属**：产品经理的产出建议放 `work/runs/<runId>/01b-product.json`，**不进最终 20 键 JSON**（最终 JSON 固定 20 键，不增不减）；它插入的段落最终体现在 `body_markdown` 与 `html` 里。

## 六、数据现状与已知限制

**规模**：产品 **62** 篇（59 个在售 + 3 个仅存手册的旧品）、集合 **16** 篇、场景 **5** 篇、手册 **26** 篇。

**分类分布**（`分类` 字段已归一，不再混用 Shopify 的自由文本）：

| 分类 | 数量 | | 分类 | 数量 |
| --- | --- | --- | --- | --- |
| 像素显示屏 | 12 | | 蓝牙音箱 | 4 |
| 像素音箱 | 11 | | 充电器 | 3 |
| 套装 | 10 | | 桌面布置 | 3 |
| 像素背包 | 8 | | 未分类 / 其他 / 礼品卡 / 服务 | 5 |
| 卡拉OK音箱 | 6 | | | |

**商品类型**：`单品` 30、`套装` 29、其余为礼品卡 / 礼品 / 服务。**只有 `单品` 适合植入**；其中**单品且有手册 = 24 个**，是最干净的候选池。

**已知缺口**：

1. **3 份手册抓取失败**：`MiniToo`、`SongBird SE`、`FlowToo` 的多语种 PDF（MiniToo 那份 3.9MB，Firecrawl 反复超时）。
   这三个产品的 `能力小节` 与 `包装清单` 为空，但 `标签`（12–14 个）与 PDP 正文仍在，**扫描匹配不受影响**。需要补齐可单独重试这三个 URL。
2. **3 个产品已不在 `products.json`**（疑似下架）：`divoom-ditoo-mic-microphone-speaker`、`divoom-spark-pop-bluetooth-speaker-portable-small-speaker`、`pixoo16`。它们没有 `价格`，`在售` 为 `false`。
3. **`未分类/其他` 5 个**都是礼品 / 赠品 / 服务类，不参与植入，无需修正。
4. **PDP 正文残留约 5 行页面控件**（优惠码、支付方式）。判断时以 `## 手册功能小节` 与 `## PDP 描述` 为准，PDP 正文只作补充阅读。
5. **本库是快照**：上下架、价格、手册都会变。刷新方式：

   ```bash
   python3 fetch_brand.py --phase all        # 抓（已有原始缓存会跳过）
   python3 fetch_brand.py --phase reclean    # 只按新规则重清洗，不联网
   python3 build_brand_library.py            # 重新组装
   ```

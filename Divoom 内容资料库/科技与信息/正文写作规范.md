# 科技与信息｜正文写作规范

**本栏目正文主线：** 直接答案 → 机制／变量 → 区分和验证 → 实际边界；避免解释文章被维修步骤接管。

## 1. 文章承诺

读完必须让用户**理解**：知道现象背后的机制、关键变量，以及这个解释在什么范围内成立。

## 2. 开头

写 2 段、合计约 80–125 个英文词；这是本栏目 22 篇样本开头中位 2 段、101 词的可执行带宽。第一段首句用“在条件 X 下，变量 Y 通过机制 Z 导致现象 A”回答 why/how，随后说明读者可以观察到什么，不能用“很多人会问”代替因果。第二段指出至少一个会使该解释失效的条件，并点明下文将区分的变量；若存在多个可能机制，先说判断依据，暂不把其中一个写成定论。

不要在开头放品牌宣传或维修流程。某现象若涉及电气与电池、安装与坠落、防水与进水、儿童与隐私，先给停止使用的条件，再讨论成因；安全边界不能藏在末尾。

## 3. 正文推进

每个 H2 以“上一节尚未解释的是哪一个变量”为入口：首段承接该变量，下一段给因果链及其适用条件，再用可观察差异区分竞争解释，末段交代检验能说明什么及不能说明什么。普通节以 3–5 个正文段落、合计约 110–185 个英文词为检查带宽；22 篇样本中位是 4 段、143 词。一个 H2 只承担一个解释问题，段尾必须留下下一节需要澄清的变量或边界，不靠重复定义凑长度。相邻节若都声称解释同一现象，应标出各自解释的是触发条件、传递机制还是观察偏差；无法区分职责，就合并。把“与现象同时发生”误写成“导致现象”的句子须有排除其他变量的证据，否则降格为相关观察。

每写一个解释段，先列其所回答的用户子问（“是什么因素”“为什么在该条件下不同”“什么观察能反驳解释”）；若答案与前段只换说法，就合并，下一段必须增加一个新变量、可辨别信号或失效条件。并列的两三种变量可用清单；同一指标跨多个条件且口径一致时可用表格，表格下仍写判断句。本栏目样本中带清单的节有 62 个、带表格的节有 28 个，形式取决于变量关系，不设置数量指标。若连续两段变成“按某键→进入某菜单→重试”，已从机制解释滑成维修教程：保留可观察的区分信号，删去操作序列。全文英文正文按流程契约保持 1200–2200 词，不写 H3。

## 4. 证据与产品提及

每个涉及 Divoom 的机制句逐项回查 `实体库/`：现象看`状态与症状`，产生机制看`功能与能力`与`部件`，连接条件看`接口与依赖`、`条件与限制`；任何数字另查`指标与阈值`，风险边界查`结果与风险`。记录“哪一句由哪一组支持”；查不到就删除断言或数字，不得改写成“约”“大概”。一般原理或外部标准须核验其适用范围，再与实体库所能支持的 Divoom 事实分开写；外部标准不能替 Divoom 补参数。

只在品类、部件或能力与该因果链有关时提 Divoom。型号名以 `../品牌资料库/产品/` 的官方命名为准，自创或拼错的型号名是硬伤；一般指代优先用品类或部件词。配件是否随附、能否单独购买一律写“以商品页为准”。Momcozy / KTC 实例只提供结构证据，其产品事实、参数、医疗建议、测试结论和链接不得进入成稿或本规范的例子。不得给价格、品牌排名或“绝对最佳”结论。本阶段不写内链、meta、FAQ；任何安全处理先写停止条件。

## 5. 栏目专属结尾

给**边界**：说明结论在什么条件下成立、什么条件下不成立，以及读者该据此判断什么。
